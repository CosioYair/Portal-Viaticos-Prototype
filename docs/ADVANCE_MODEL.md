# Anticipo — modelo y reglas (US-14 · US-15 · APPROVED · CLOSED 2026-10-21)

Registro canónico por folio: `src/features/advance/advance-data.js` (= `prototype/us14-data.js`, `window.SMV_ANT`). Lógica de referencia: `src/features/advance/advance.js`.

## Reglas

436. **ONE CANONICAL ANTICIPO RECORD PER FOLIO** (`us14-data.js › SMV_ANT.ANTICIPOS` + session `an.recs`; `antRecs/antOf`): US-14 creates it, US-15 operates it; never copies the trip (reads `svAllReqs()`). Fields: folio · uid · estado · propuesta (FROZEN at submit) · sol / aprobado (per concept) · declaración · pago (SAP, masked) · cadenaIds + decisiones (append-only, one per step) · lock · contab (póliza) · pp (propuesta de pago) · transfers[] (incl. second transfer US-16 as ADJUSTMENT of the same record) · motivo. Estados: pendAut · autorizado · contabilizado · porTransferir · realizado (ANT_Realizado) · devuelto (reabierto) · rechazado · cancelado. «En proceso» = capture (not persisted). History is RECONSTRUCTED from the record (`antHist`); every transition also writes Bitácora (`antEv`, areas Anticipo / Autorización / Contabilización / Presupuesto).

437. **ELIGIBILITY = one resolver `antElig(r)`** (screen + «server»): externo → «No aplica · viajero externo» (no record possible) · perfil sin anticipo / Director E-ED (`anticipoNA`, rule 253) → No aplica + «Ir a Comprobación» · trip not yet approved → «Después de la aprobación» · open record → existing (one open per trip, `PARAMS.abiertos`) · sin tarifa «Anticipo · monto máximo autorizado» → blocked · viaje iniciado/concluido → «Viaje vencido» · < 5 días de antelación (`PARAMS.antelacionDias`, distinct from the 4 days of the travel request) → blocked · cuenta SAP no vigente → blocked with update route. Traveler profile decides eligibility/policy; functional role never.

438. **SYSTEM PROPOSAL = `antPropuesta(r)`** from the folio's destinations and EFFECTIVE values (excepción individual → política del perfil → parámetro global): Hospedaje (hotel nights × c1 / r3) · Alimentos (days × daily cap by number of external meals, c2 / r2) · Tintorería (global) · Gasolina / Casetas (auto particular, c7/c8) · Taxi (weekly tariff by destination hospital × weeks, editable) · Autobús / Vuelos shown as $0 with reason. Total = min(Σ concepts, tope) where tope = r14 exception (NEW rule in REGLAS_EXC, demo e6 u09) or tariff c4; if Σ > tope, concepts are scaled proportionally and marked. Origin chip per concept + «Consultar el detalle del cálculo».

439. **REQUESTED ≤ PROPOSED (hard)**: only `PARAMS.editables` (Taxi, Autobús) accept a LOWER amount; per-concept error under the field with the maximum and its origin; total ≤ proposal; declaración obligatoria; validated again in `antSubmit` (owner only, idempotent `_antBusy`). Requesting less is valid and labeled as such. «Monto propuesto por el sistema» and «Monto de anticipo solicitado» are separate lines.

440. **AUTHORIZATION CHAIN = `antChain(uid)`** (US-15: Director inmediato → Dirección Corporativa, SAP structure; NOT the US-09 travel chain; no DGA/CH CO steps; duplicates/self removed). Tray **Autorización › Anticipos** (`aut-ant`, DIR · CHC · DGA ✓, actions CO + AU) with Por autorizar / Resueltos por mí; population = signer in turn (`antPending`) feeds tab counter, sidebar sum and bell «Requieren mi acción». Reject = catalog (`MOTIVOS_RECHAZO`) + text (required for «Otro motivo»), visible to the traveler.

441. **CONTABILIDAD = Contabilización › Solicitud de anticipo** (`con-ant`, CON; actions CO · VA Validar = tomar, contabilizar, rechazar/cancelar · **PG Procesar pago** NEW = propuesta de pago, confirmar transferencia, devolución). Tabs: Por contabilizar · Propuesta de pago · Por transferir · Realizados · Rechazados y cancelados · En autorización (read-only); counters on the first three = sidebar sum. Take (lock; other analysts read-only) → contabilizar (approved per concept ≤ solicitado, justification required if it differs, visible to the collaborator; póliza; once) → propuesta de pago grouped by sociedad + banco (accounts must be vigentes; export CSV) → confirmar depósito (fecha no futura + referencia; individual or batch with consecutive references; importe distinto ⇒ justificación) → ANT_Realizado + traveler notice (monto, cuenta, plazo desde el fin del viaje). Devolución bancaria → devuelto (causa catalog) → reincluir en propuesta. Second transfer (US-16) = adjustment row of the same anticipo. MODO DEMO «Condición del anticipo»: cuenta no vigente · viaje vencido · falla de integración con SAP (nothing applied, «Reintentar»).

442. **BUDGET = CONSUMED** (rule 419 semantics unchanged; Movimientos presupuestales still Carga inicial · Suplemento · Bloqueo): the approved folio is already Comprometido (Reserva). At the LAST authorization only the difference above the folio's net reserve is committed (Reserva «compromiso adicional del anticipo»; e.g. Taxi is not in the travel estimate). Confirmed deposit = ONE «Anticipo» row in Movimientos de bolsa (→ En tránsito); devolución = negative «Anticipo» row; contab rejection/cancel releases only the additional commitment. Seed folios get their Reserva / Anticipo rows from `antSeedMovs()` (injected in `presData`). The traveler never sees entity figures.

443. **SAME JOURNEY / HOME / MIS VIAJES**: stage 2 from `antStage(r)` (Disponible para solicitar · Pendiente autorización nivel n de m — firmante · Autorizado · en contabilización · Transferencia en proceso · Depositado fecha · monto · Transferencia devuelta · Rechazado (red) · No aplica); CTA `antCta` = SOLICITAR ANTICIPO / VER ANTICIPO (same folio); Mis viajes «Anticipo» section `antSec` + «Qué sigue» `antNext`; Home Contabilidad tray «Anticipos autorizados» + KPI «Anticipos por transferir» from the same records. Companion = own folio, own proposal, own anticipo (origin untouched).

450. **ANTICIPO SOLO POR CONTABILIDAD (client 2026-10-16, supersedes rule 440 and the authorization part of 441/442)**: no Director / Dirección Corporativa chain; menu option «Autorización › Anticipos» (`aut-ant`) removed from MENU. On submit the record goes straight to estado `autorizado` = «Por contabilizar» (seed `pendAut` records are normalized the same way); the traveler may cancel while not contabilizado. Contabilidad's single action **«CONTABILIZAR ANTICIPO»** (no separate «Tomar anticipo»; the lock is still checked) contabiliza and programs the payment; the additional commitment above the folio reserve is now registered AT CONTABILIZACIÓN. Card «Contabilización y pago» replaces «Autorización y procesamiento».

451. **FECHAS POSIBLES DE DEPÓSITO** (`antFechasDep`): next 2 payment days (demo: martes y jueves, `PARAMS.diasPago`) from 2 business days after the later of submit / today; shown in the confirmation, the success modal, the traveler's detail (card «Contabilización y pago»), journey stage and «Qué sigue»; stored on the record (`fechasDep`).

452. **CONCEPTOS DEL ANTICIPO**: column «Máximo propuesto» removed (traveler and Contabilidad; the input still shows «máx.»). «Agregar otro concepto» (Autobús · Casetas · Gasolina · Estacionamiento · Tintorería · Otros gastos de viaje) adds editable lines without tariff («Agregado por el colaborador», removable); total ≤ tope del anticipo (`antPropForm`).

453. **RECHAZO DE ANTICIPO (Contabilidad)**: only «Detalle del motivo *» (no Acción Rechazar/Cancelar, no catalog); button «RECHAZAR ANTICIPO».

454. **ICONO DE RESULTADO NEGATIVO (permanent, global UI rule, 2026-10-16)**: the shared result modal shows a RED X (bg #FEEDED, border/stroke #F25757) instead of the green check whenever the outcome is a cancellation, rejection, deletion, revocation, deactivation or a submit that did not proceed (title regex in `okVals`, or `negative: true` in `notifySuccess`).

455. **HOSPEDAJE EN EL RESUMEN DEL VIAJE (anticipo)**: no «n de n noches»; «Hotel externo: n noches · en hospital: n noches» (days stay in Fechas).

456. **CONTABILIZAR = PROGRAMAR PARA PAGO + DEPÓSITO AUTOMÁTICO POR JOB DE SAP (client 2026-10-16, supersedes the manual «Confirmar depósito» of rule 441)**: Contabilidad contabiliza in BATCH («CONTABILIZAR Y PROGRAMAR PAGO (n)» in Por contabilizar, `antContabLote`, approved = solicitado, grouped by sociedad + banco = propuesta de pago) or individually from the detail («CONTABILIZAR ANTICIPO», when an amount must be adjusted); both leave the record «Programado para pago» (`porTransferir`) with `pp.fechaPago` = next martes/jueves. SAP transfers martes y jueves; at 12:00 a JOB reads the deposits via web service, marks them Realizado (ANT_Realizado, fecha = programmed date, SAP reference, actor «Proceso automático») and notifies the collaborator by e-mail + Portal (`antJobSap`; MODO DEMO button «Ejecutar consulta a SAP» in the tab). No manual date/reference capture. Tabs: Por contabilizar · Por programar (cuenta no vigente / devolución bancaria → «Programar pago») · Programados para pago · Realizados · Rechazados y cancelados. Traveler: «Fechas posibles de depósito» (confirmation row, success-modal note, detail) until contabilizado, then «Depósito programado <día fecha>». Pending: the job's exact contract (WS fields, retry if SAP fails, what if the deposit is not found that day).

466. **CONTABILIDAD NO MODIFICA IMPORTES (manager + client 2026-10-19; supersedes the «aprobado ≤ solicitado / justificación» part of rule 441, the individual-adjust path of rule 456, and every Aprobado/Diferencia element)**: the collaborator's requested amount is IMMUTABLE in Contabilidad. Valid ⇒ CONTABILIZAR; incorrect ⇒ RECHAZAR with motive; the collaborator then requests again with the correct amount (antElig: a rejected anticipo no longer blocks a new request, like a cancellation — resolves the pending «new request after rejection»). Removed: columns APROBADO and DIFERENCIA, the «Editable solo a la baja» inputs on the accounting side, «Aprobado (a contabilizar)» total, «Justificación de la diferencia» (textarea, validation, record field `justificacion`, banner, notices, history), `rec.aprobado` (antLines: tApr is only an alias of tSol).

467. **REVISIÓN DE CONCEPTOS (Contabilidad)** = read-only table **Concepto · Solicitado · Monto máximo por política** (every concept shows its policy amount; added concepts = «Hasta $tope · tope del anticipo»; Autobús without tariff = «Sin tarifa configurada», pending tariff), totals «Monto máximo determinado por sistema» (tope + origin) and «Solicitado». Origin chip «Por hospital destino» uses the policy (blue) tone. «Consultar el detalle del cálculo» only for Contabilidad.

468. **EL VIAJERO NO VE TARIFAS MÁXIMAS (client 2026-10-19)**: the system validates the maximum internally and blocks larger amounts, but the traveler never sees per-concept ceilings or the anticipo tope: no «máx.» hint, no «Máximo propuesto por el sistema» line (form, confirmation, Mis viajes, list «Hasta $…», «Qué sigue»), no tariff breakdown (`calcT` = neutral text: «2 noches en hotel externo»), no calculation detail; error texts say «excede el máximo permitido por la política» without the figure. Fixed-by-policy concepts still show their system-calculated amount (US-14 proposal); editable concepts (Taxi, added concepts) start EMPTY (= $0) and the traveler types what he needs. Supersedes the «máx.» part of rule 452 and the visible-maximum parts of 438/439.

469. **PESTAÑAS DE CONTABILIZACIÓN › SOLICITUD DE ANTICIPO (client 2026-10-19; supersedes the tab list of rule 456)**: **Por contabilizar · Programados para pago · Realizados · Rechazados y cancelados · Complemento**. «POR PROGRAMAR» NO LONGER EXISTS (no tab, counter, action «Programar pago», `antPropuestaPago`, state `contabilizado` — legacy records normalize to `porTransferir`). Por contabilizar = individual («Gestionar» → «Contabilizar anticipo» / «Rechazar anticipo») or MULTIPLE with the global checkbox (column + select-all on desktop, «Seleccionar todos (n)» on cards): button **«Contabilizar seleccionados (n)»** (n = selected; disabled at 0; only eligible rows = not taken by another analyst and with a vigente account). Each anticipo gets its own póliza. Account not vigente ⇒ cannot be contabilized (banner + disabled button) — PROTOTYPE INTERPRETATION / PENDING CLIENT CONFIRMATION.

470. **PROGRAMADOS PARA PAGO = CONSULTA DEL ESTATUS DEL ERP (client 2026-10-19)**: Contabilidad processes the payment in the ERP; the Portal only shows the ERP status («Por transferir» + previsto fecha, or transferencia devuelta). «Exportar propuesta de pago» and the propuesta de pago id (PP-…) were removed from the UI (PROTOTYPE INTERPRETATION of «solo es una consulta» — PENDING CLIENT CONFIRMATION). The ERP consultation (production: automatic martes y jueves) is triggered in the prototype by the outlined dark-gray control **«SIMULACIÓN · CONSULTAR ESTATUS ERP»** + note «MODO DEMO · solo prototipo»; «Condición del anticipo» adds «Respuesta del ERP: por transferir» (records `erp.estatus`, no deposit) and keeps «Falla de integración». Default simulated answer = «Depositado» ⇒ **Realizados** (no manual date/reference capture by Contabilidad). The word «SAP» is never shown (rule 465): the client's «Consultar estatus SAP» is labelled «Consultar estatus ERP».

471. **PÓLIZA EN TODAS LAS PESTAÑAS**: list column «Póliza» (= `contab.poliza`, one canonical value; «—» before contabilizar; searchable), Datos generales «Póliza contable» («— (se asigna al contabilizar)»), card «Contabilización y pago» and the success modal.

472. **SOLO CONTABILIDAD RECHAZA EL ANTICIPO (client 2026-10-19)**: rejection by `con-ant` VA (Contabilidad); the card «Contabilización y pago» shows ONE step «Contabilidad / Tesorería» with Rechazado + responsible + date + «Motivo» (no Director step; seed 00076 now rejected by Contabilidad). Motive = «Detalle del motivo *» only (rule 453). That the rejection is offered ONLY in Por contabilizar (not after contabilizar) = PROTOTYPE INTERPRETATION / PENDING CLIENT CONFIRMATION.

473. **DETALLE DE CONTABILIDAD**: breadcrumb «Inicio › Contabilización › Solicitud de anticipo › <pestaña> › Folio n» + eyebrow «Solicitud de anticipo · <pestaña>» (location); header WITHOUT destino/fechas (redundant with «Resumen del viaje»); header row **«Notificación enviada · fecha · evento» + «REENVIAR NOTIFICACIÓN»** (PROTOTYPE INTERPRETATION of the page-4 arrow note — PENDING CLIENT CONFIRMATION) (bell notice + correo to the collaborator with the current status, Bitácora; `antResend`); section «Seguimiento del anticipo» REMOVED for Contabilidad (kept for the traveler); Datos generales: «Cuenta •••• n» WITHOUT titular name, «Vigencia de la cuenta» = date from the ERP / policy-modification table (`VIGENCIA_CUENTA`, default 31/12/9999 — the client wrote «31.12.999», read as the open-ended ERP date). Success modal after contabilizar: no propuesta de pago id.

474. **COMPLEMENTO = PESTAÑA PROPIA** after Rechazados y cancelados: second transfer of the SAME anticipo (US-16 adjustment); counter = complements por transferir; action «Confirmar complemento» only from this tab (removed from Realizados). Realizados keeps «Registrar devolución bancaria» (pending question).

475. **NOTIFICACIONES DEL ANTICIPO** (PROTOTYPE INTERPRETATION / PENDING CLIENT CONFIRMATION): contabilizar now also notifies the collaborator («contabilizado y programado para pago: depósito previsto …»); rejection text adds «Solicítalo de nuevo con el importe correcto».

476. **INICIO DE CONTABILIDAD SIN TERMINOLOGÍA DE AUTORIZACIÓN DEL ANTICIPO (manager 2026-10-19, shared integration caused by US-14/US-15; US-02 not reopened)**: tray «Anticipos autorizados» → **«Solicitudes de anticipo»** (same canonical population as the module: por contabilizar · programados para pago · devueltos · depositados; detail = CECO · Solicitado / Por transferir / Depositado · cuenta, second line = «Enviado fecha» or «Contabilizado fecha · póliza»); KPI «Anticipos por transferir» → **«Anticipos en proceso»** (por contabilizar + programados + devueltos, same records); help text and the static demo notice no longer say «autorizado». The internal state key `autorizado` (= Por contabilizar) and the US-03 tariff name «Anticipo · monto máximo autorizado» keep their legitimate meaning; the unreachable `aut-ant` route code (menu option removed, rule 450) is dead code to drop at source sync.

491. **ANTICIPO RECHAZADO = COLOR POR ACCIÓN POSIBLE (client 2026-10-20)**: rejected by Contabilidad and the collaborator CAN still request again (trip vigente) ⇒ **amarillo** («Rechazado · solicítalo de nuevo» in the Anticipo list, Mis viajes «Rechazado · por solicitar de nuevo»); rejected with no further action possible ⇒ **rojo** («Rechazado»). Never blue for a rejection. «No aplica · solicitud rechazada» (the TRIP was rejected, the anticipo never existed) stays gray = No aplica.

492. **«REENVIAR NOTIFICACIÓN» SOLO EN REALIZADOS (client 2026-10-20; refines 473)**: the detail header of Contabilidad keeps «Notificación enviada · fecha · evento» in every tab, but the action «REENVIAR NOTIFICACIÓN» appears ONLY when the anticipo is Realizado (depositado) — not in Por contabilizar, Programados para pago, Rechazados y cancelados or Complemento (`canResend`, also enforced in `antResend`).

493. **PROGRAMADOS PARA PAGO · DESCARGAR PROPUESTA DE PAGO (client 2026-10-20; supersedes the «export removed» interpretation of rule 470)**: next to «Simulación · Consultar estatus ERP» (now outlined BLUE like every secondary action, no dark-gray variant) the tab shows **«DESCARGAR PROPUESTA DE PAGO (EXCEL)»**: one file (CSV UTF-8, opens in Excel) with ALL anticipos pending payment (Por transferir + Transferencia devuelta), regardless of search/filters — Folio · Colaborador · No. · Sociedad · CECO · Póliza · Importe · Moneda · Banco · Cuenta (masked) · Vigencia cuenta · Estatus · Fecha prevista de pago; Bitácora «Descargó la propuesta de pago». Native .xlsx format = to define at source sync.
