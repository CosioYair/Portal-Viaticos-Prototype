# HOME_VISIBILITY_MATRIX — Home scope by role (canonical developer reference)

Principle (client rule): **a user only sees Home information within the scope of their responsibilities.** Home content = functional role + organizational scope + traveler capability + specific permissions + personal vs. operational context. **Traveler capability never escalates data access**: it only adds the user's OWN trip card (shared JourneyProgress, most recent request) and own traveler actions. Organizational budget indicators require documented responsibility (Presupuesto › Monitor ✓ in `navigation.json`) or an explicit permission (P). Least scope wins.

Data: `src/data/home.json › homes[user].summary.scope` or `summaries[].scope` (`personal` · `operational` · `organizational`) and `trays[]` (`columns`). Organizational budget block = **Planeado · Ejercido · Comprometido · PRE disponible**, where **PRE disponible = Planeado − Comprometido** (Ejercido is the consumed part of Comprometido and does not change the formula; «Ejercido» is the canonical user-facing term, never «Consumido»). Lists follow docs/TABLE_LIST_STANDARD.md (consistent columns, search + filters, sorting, pagination). Update this file whenever a User Story changes Home visibility.

Notes
- Personal amounts and organizational totals never share a field or a card; the summary title names the scope (e.g. «Presupuesto de viáticos · HSM Chihuahua»).
- Organizational origin (Hospital / Corporativo) appears only where it helps the role process the record (consolidated queues, Dirección / CH CO lists); never in `personal` trays.
- Mock budget values (`summary.personalBudget`, organizational KPIs) are display data; the production formulas belong to Presupuesto (Alcance: monto ejercido / comprometido / saldo / % utilización) and are not approved here.
- Anticipo rule (all traveler-capable roles): No aplica only for perfil Director with personnelGroup E or ED (DGA does not inherit it) (`users.json › personnelGroup`, `navigation.js › anticipoApplies`); the journey keeps stage 2 in place as «No aplica».
- Every tray follows docs/TABLE_LIST_STANDARD.md: one meaning per column, search + contextual filters, sortable headers, pagination.
